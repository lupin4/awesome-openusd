The library stack

OpenUSD is about 60 libraries in four tiers. Opinions start as specs in Sdf layers, Pcp composes them, Usd serves the resolved stage, schemas give it meaning, and Hydra draws it.

Select a library to see what it owns, the types you will touch, and the mistake people make with it. Source lives under pxr/base, pxr/usd, pxr/imaging, pxr/usdImaging and pxr/exec.

Rule of thumb. Write with Sdf when you generate lots of data (it skips composition and runs inside Sdf.ChangeBlock). Read with Usd when you need the truth a user sees. Renderers never read layers; they read what Hydra pulls from the stage.
</Manual/Composition>

Composition

Composition builds one prim index per prim: a tree of nodes, each a layer stack reached through an arc. Opinions are read from the strongest node first. The strength order is LIVERPS.

#LetterArcOne-line purpose
1LLocal (layer stack)Opinions in the current layer stack, sublayers included
2IInheritsBroadcast edits from a class to every prim that inherits it
3VVariantSetsSwitchable branches of opinions
4ErElocatesMove namespace that came in through an arc
5RReferencesBring a prim from another layer into this namespace
6PPayloadsReferences you can unload
7SSpecializesA base whose opinions lose to everything else

Play with strength

Each row is an arc holding an opinion for inputs:roughness. Switch rows off, change values, and watch which one resolves.

Every arc, in depth

Llocal

Local opinions and sublayers

A layer stack is a root layer plus its sublayers, recursively. Earlier entries in subLayers are stronger, and a layer's own opinions beat everything in its sublayers. The session layer sits above the root layer and is never saved with it.

#usda 1.0
(
    subLayers = [
        @./lighting.usda@,                       # strongest
        @./anim.usda@ (offset = 10; scale = 2),  # retimed: t' = 10 + 2t
        @./layout.usda@                          # weakest
    ]
)
  • Layer offsets compose down the stack: a sample at time t inside anim.usda appears at offset + scale × t on the stage.
  • stage.MuteLayer(id) removes a layer's opinions without editing files. Use it to isolate departments while debugging.
  • The layer stack is the unit every other arc targets. A reference to asset.usd brings in asset.usd and all of its sublayers.
Iinherits

Inherits and class broadcast

A prim that inherits a path receives every opinion authored at that path, in any layer stack along the way. Targets are usually class prims, which stage traversal skips by default.

class "_class_Tree"
{
    color3f[] primvars:displayColor = [(0.20, 0.45, 0.20)]
}

def Xform "Oak_01" (
    prepend inherits = </_class_Tree>
)
{
}
  • Implied inherits. When a referenced asset inherits a path outside its referenced prim, that path is also looked up in every stronger layer stack. A shot can author class "_class_Tree" and recolor every tree it references, beating the asset's own opinions.
  • Inherit paths inside the referenced prim are remapped through the reference; paths outside it stay global.
  • Each inherit adds nodes to every inheriting prim's index, even when the class is empty. Use them deliberately on large sets.
Vvariants

VariantSets

A variant set is a named group of alternative opinion branches. The selection is itself metadata, so it resolves by strength: the strongest layer that sets variants = { string lod = "…" } decides.

def Xform "Robot" (
    variants = { string lod = "high" }
    prepend variantSets = "lod"
)
{
    variantSet "lod" = {
        "high" (
            prepend payload = @./geo_high.usdc@
        ) {
        }
        "low" (
            prepend payload = @./geo_low.usdc@
        ) {
        }
    }
}
  • Opinions inside a variant are weaker than local opinions on the same prim in the same layer stack. Author everything a variant should control inside the variant only.
  • Variants may hold any arc, including references, payloads and further variant sets. Nested sets are composed in the order selections make available.
  • Author into a variant from Python with with vset.GetVariantEditContext(): … after SetVariantSelection.
  • Fallback selections apply when nothing is authored: Usd.Stage.SetGlobalVariantFallbacks() before opening, or a plugin's plugInfo.json.
Erelocates

Relocates

Relocates move namespace that arrived through an arc to a new path, without editing the source asset. They are layer metadata. v26.11 removed prim-level relocates from Sdf entirely (composition never used them), so layers with relocates on a prim no longer parse.

#usda 1.0
(
    relocates = {
        </Char/Rig/Controls/Anim>: </Char/Anim>
    }
)
  • The source path becomes inaccessible; opinions must be authored at the target.
  • Mainly a character-pipeline tool: expose deep rig controls at a stable, short path for animators.
Rreferences

References

A reference grafts a prim (and its subtree) from a layer onto the referencing prim. The referenced prim takes the referencing prim's name and path.

def "Chair_01" (
    prepend references = @./assets/chair.usd@</Chair>
)
{
    double3 xformOp:translate = (1.2, 0, 0)
    uniform token[] xformOpOrder = ["xformOp:translate"]
}

over "Chair_02" (
    prepend references = </Chair_01>   # internal reference, same layer stack
)
{
}
  • No prim path means the target layer's defaultPrim. Set it on every asset.
  • References are encapsulated: they bring the target prim's subtree, not its ancestors' opinions or root-level siblings.
  • Arcs are list-ops: prepend, append, delete, or an explicit list that replaces weaker ones.
  • Asset paths anchor to the layer they are written in, never to the stage.
Ppayloads

Payloads

Payloads compose like references, one strength level weaker, and can be left unloaded. That makes them the boundary between a cheap asset interface and its heavy data.

from pxr import Usd
stage = Usd.Stage.Open("set.usda", Usd.Stage.LoadNone)   # nothing heavy yet
robot = stage.GetPrimAtPath("/Set/Robot_01")
print(robot.HasPayload(), robot.IsLoaded())               # True False
stage.Load(robot.GetPath())                               # load one subtree
rules = stage.GetLoadRules()                              # or edit rules wholesale
rules.LoadWithoutDescendants("/Set")
stage.SetLoadRules(rules)
  • An unloaded payload hides everything inside it. The prim still shows what is authored above the payload: kind, assetInfo, variant sets, extentsHint.
  • Put the payload on the component root, and keep variant selections and transforms outside it so layout can work unloaded.
Sspecializes

Specializes

Specializes behaves like inherits, except the base's opinions lose to every other opinion on the specializing prim, from any layer stack. Refinements survive changes to the base.

def Material "Metal"
{
    float inputs:roughness = 0.4
}

def Material "RustyMetal" (
    prepend specializes = </Looks/Metal>
)
{
    float inputs:roughness = 0.8   # always beats edits to Metal, even from a shot
}
  • Use it for material libraries and "same as X, except" variations.
  • Compare with inherits in puzzle 6 below: the same shot edit wins with inherits and loses with specializes.

Rules that apply to every arc

  • Recursion. Inside every arc target, LIVERPS applies again. A whole stronger subtree beats a whole weaker one.
  • Ancestral arcs. An arc on /Set also contributes opinions to /Set/Chair. Ancestral opinions are weaker than arcs authored directly on the descendant of the same type.
  • Expression variables. expressionVariables = { string SHOT = "s010" } in layer metadata, and @`"./shots/${SHOT}/anim.usda"`@ in sublayers, references, payloads, asset attributes and variant selections. One template layer then serves every shot. From v26.11 a variable can carry a quoted fallback: ${SHOT:'s000'}.
  • Value clips are not an arc. They stream time samples from many files and resolve just below the layer that declares them.

Value resolution & debugging

Composition decides which opinions exist and in what order. Value resolution walks that order and returns one value per property per time.

The algorithm for an attribute at time t

  1. Walk the prim index nodes strongest to weakest, and within each node its layers strongest to weakest.
  2. Stop at the first layer holding a value source for the property: a spline or time samples (these beat a default in the same layer), a default, or value clips declared there (clips sit just below that layer's own opinions).
  3. Time samples interpolate linearly by default (stage.SetInterpolationType(Usd.InterpolationTypeHeld) switches to held). Before the first sample you get the first value; after the last, the last. Non-numeric types are always held.
  4. A value block (= None) stops the walk: the attribute reports no authored value.
  5. No opinion anywhere: the schema's fallback from the prim definition, or nothing.
Consequence people miss. A default in a stronger layer beats time samples in a weaker layer. An animator's curve vanishes when someone authors a static value in lighting.

Gaussian splats: ParticleField3DGaussianSplatv26.03 · UsdVol

3D Gaussian Splatting data is a first-class prim. ParticleField is the base prim; per-particle data comes from attribute API schemas, each with a float and a half-precision attribute (consumers prefer float when both exist). On ParticleField3DGaussianSplat all of them, plus the GaussianEllipsoid kernel, are built in: you author the attributes directly, with no apiSchemas line.

PieceAttributes / values
ParticleFieldPositionAttributeAPIpoint3f[] positions, point3h[] positionsh; the length sets the particle count
ParticleFieldOrientationAttributeAPIquatf[] orientations, quath[] orientationsh
ParticleFieldScaleAttributeAPIfloat3[] scales, half3[] scalesh: affine scale of each particle's kernel
ParticleFieldOpacityAttributeAPIfloat[] opacities, half[] opacitiesh: linear 0–1; missing data means fully opaque (1.0)
ParticleFieldSphericalHarmonicsAttributeAPIfloat3[] radiance:sphericalHarmonicsCoefficients (+ …h), int radiance:sphericalHarmonicsDegree = 3. Degree N stores (N+1)² coefficients per particle, contiguous per particle. Missing data falls back to a grey DC term (0.5, 0.5, 0.5).
Kernel APIsGaussianEllipsoid, GaussianSurflet, ConstantSurflet
projectionModeHintperspective (default) or tangential
sortingModeHintzDepth (default), cameraDistance, rayHitDistance

Arrays longer than the particle count are truncated; shorter ones are ignored. Renderers may ignore both hints. The reference renderer is hdParticleField.

def ParticleField3DGaussianSplat "Capture"
{
    point3f[] positions = [(0, 0, 0), (0.1, 0, 0)]
    quatf[] orientations = [(1, 0, 0, 0), (1, 0, 0, 0)]
    float3[] scales = [(0.01, 0.01, 0.01), (0.02, 0.01, 0.01)]
    float[] opacities = [0.9, 0.6]
    int radiance:sphericalHarmonicsDegree = 0          # 1 coefficient per particle
    float3[] radiance:sphericalHarmonicsCoefficients = [(0.8, 0.2, 0.2), (0.2, 0.2, 0.8)]
}
Multiple level of detail: UsdLodv26.08

A standard way to author detail levels and let the runtime choose, without editing the scenegraph or using variants.

In usda the names are all-caps LOD; C++ classes are UsdLodRootAPI and so on.

  • LODRootAPI marks the root: rel lod:heuristics and int lod:default:index (fallback 0). The root's children are the levels by index: LOD0 (most detail), LOD1, LOD2.
  • Heuristics are prims: LODDistanceHeuristic (center) and LODScreenSizeHeuristic (extent, projectionMethod = projectedSphere). Both take uniform thresholds, blendThresholds, a boundingVolume rel and a lod:domain token.
  • LODOverrideAPI forces a level: token lod:override:mode (fallback inherited) and float lod:override:index. The index is a float, so fractional values express cross-fades.
  • Selection order: override, then each heuristic in turn, then the default index.
  • The schemas only describe the levels. Each renderer must implement the selection, and the changelog says Hydra support is still under development.
def Xform "Tree" (
    prepend apiSchemas = ["LODRootAPI"]
)
{
    rel lod:heuristics = </Tree/ByDistance>

    }

    def Xform "LOD0"
    {
    }

    def Xform "LOD1"
    {
    }

    }
}

Profiles and capabilitiesv26.08

Profiles answer "can this tool faithfully open, edit and round-trip this asset?" A capability is a reverse-domain identifier such as usd.geom.skel or usd.image.jpeg. Capabilities form a graph: usd.image.jpeg implies usd.image. A profile is a named set of them.

  • Three domains: layer (encodings, compression), prim (schema features such as skinning), application (physics simulation, an import path).
  • The applied schema is ClaimsAPI (C++ UsdProfilesClaimsAPI, library usdProfiles). The release blog calls it a "ProfileAPI", but no schema by that name exists. It stores everything in the prim's customData["profilesInfo"]: capabilityUsages (capability → hard, soft or enhancement, written by the DCC) and profileCompatibility (profile → list of excepted capabilities, written by a pipeline audit).
  • PopulateCapabilityUsages() walks descendants and records the capabilities implied by applied schemas and layer file formats; IsCompatibleWith(profile) answers the compatibility question, honoring exceptions.
  • Schemas imply capabilities through plugin metadata (usdGenSchema accepts arrays in extraPlugInfo). usdchecker support is planned.
OpenExecv25.08 → v26.03

An execution framework for computations defined by schemas, so behavior such as rigging can live in USD. v26.03 added IrFkController, the first step toward invertible rigging. Watch it; do not build production on it yet.

Core domains

UsdGeomspace, meshes, primvars
  • Stage metrics. upAxis falls back to Y and metersPerUnit to 0.01. Set both on every root layer.
  • Transforms. xformOpOrder lists ops applied right to left in matrix terms; !resetXformStack! ignores parent transforms. Gf matrices are row-major and points multiply as v × M.
  • Mesh. points, faceVertexCounts, faceVertexIndices, normals. subdivisionScheme defaults to catmullClark: set "none" for polygonal assets or they render smoothed.
  • GeomSubset with familyName = "materialBind" assigns materials per face.
  • Imageable. visibility (inherited/invisible), purpose (default, render, proxy, guide), proxyPrim.
  • Boundable. Author extent on gprims; UsdGeom.BBoxCache computes bounds fast.
  • Cameras. Focal length and apertures are in tenths of a scene unit (millimetres at the default centimetre scale).

UsdShade + MaterialX + OpenPBRmaterials
  • A Material exposes terminals per render context: outputs:surface (universal), outputs:mtlx:surface, outputs:ri:surface.
  • Shader prims name their implementation with info:id; connections are .connect paths; NodeGraphs expose an interface of inputs:.
  • Binding: material:binding relationship (via MaterialBindingAPI), purpose-specific material:binding:full / :preview, and collection bindings. bindMaterialAs = "strongerThanDescendants" overrides child bindings.
  • Portability ladder: UsdPreviewSurface everywhere, MaterialX standard_surface or OpenPBR in production renderers, MDL in Omniverse.

{
    token outputs:surface.connect = </Looks/Painted/Surface.outputs:surface>

UsdLuxlights
  • Concrete lights: DistantLight, RectLight, SphereLight, DiskLight, CylinderLight, DomeLight, PortalLight; any geometry can emit via MeshLightAPI.
  • Brightness is inputs:intensity × 2^inputs:exposure; inputs:normalize makes it independent of light size.
  • Light and shadow linking use the lightLink and shadowLink collections on the light.
  • Dome lights: inputs:texture:file with inputs:texture:format = "latlong".
UsdSkelcharacters
  • A SkelRoot scopes skinning. Inside: a Skeleton (joints as token paths, bindTransforms, restTransforms) and skinned meshes.
  • Meshes apply SkelBindingAPI: primvars:skel:jointIndices, primvars:skel:jointWeights (with an elementSize of influences per point), skel:skeleton, primvars:skel:geomBindTransform.
  • SkelAnimation holds translations, rotations (quatf), scales, blendShapes and blendShapeWeights; the skeleton points at it with skel:animationSource.
  • Joint indices refer to the skeleton's joints order unless the mesh overrides it with skel:joints. Most broken imports are an ordering mismatch.
UsdPhysicssimulation, robotics
  • PhysicsScene (gravity), RigidBodyAPI, CollisionAPI + MeshCollisionAPI (approximation), MassAPI (mass, density, center of mass, inertia), MaterialAPI (friction, restitution).
  • Joints: RevoluteJoint, PrismaticJoint, SphericalJoint, FixedJoint, DistanceJoint, with physics:body0/body1 and local frames; limits and drives are multiple-apply (LimitAPI:angular, DriveAPI:angular).
  • ArticulationRootAPI marks a reduced-coordinate articulation (robot arms). CollisionGroup and FilteredPairsAPI control contacts.
  • Isaac Sim is USD-native on these schemas; other engines import them, so they are the portable robot description.
UsdRender, UsdVol, UsdMedia, UsdProcthe rest
  • UsdRender. RenderSettings (resolution, camera, products), RenderProduct (output file, ordered vars), RenderVar (an AOV by source name). This is how synthetic-data passes stay renderer-neutral.
  • UsdVol. Volume with OpenVDBAsset fields bound by name, plus the particle fields above.
  • UsdMedia. SpatialAudio, asset previews, and from v26.11 AuthorshipAPI for who made a subtree and with what tools.
  • UsdProc. GenerativeProcedural prims that a Hydra procedural plugin expands at render time.
  • UsdSemantics. SemanticsLabelsAPI is multiple-apply, one instance per taxonomy: prepend apiSchemas = ["SemanticsLabelsAPI:class"] and token[] semantics:labels:class = ["forklift", "vehicle"]. This is the standard place for segmentation class labels.

Asset structure

A scalable pipeline is mostly convention: a cheap asset interface, a payload boundary, a contiguous kind hierarchy and one layer per department.

The asset interface

Everything a downstream user needs without loading geometry lives above the payload: defaultPrim, kind, assetInfo, variant sets, extentsHint and a proxy purpose if you have one.

  geo.usdc         meshes, primvars, render/proxy purposes
  mtl.usda         materials and bindings (small, diff-friendly text)

Asset resolution and publishing

  • The default resolver anchors relative paths to their layer and searches PXR_AR_DEFAULT_SEARCH_PATH for search-style paths.
  • A resolver context is bound per stage (stage.GetPathResolverContext()); custom resolvers use it to pin versions per shot.
  • Publish immutable versioned files; point shots at versions through the resolver or expression variables, never by overwriting.
  • USDZ is an uncompressed, 64-byte-aligned zip of usdc/usda, images and audio. Build with usdzip or UsdUtils.CreateNewUsdzPackage().
  • Validate at publish with usdchecker (UsdValidation framework). UsdUtils.ComplianceChecker is deprecated.

The data model

  • A scene index answers two questions: GetPrim(path) returns an HdSceneIndexPrim (a primType token and a container data source), and GetChildPrimPaths(path) returns children.
  • Data sources are lazy and typed through schemas such as HdMeshSchema, HdXformSchema, HdPrimvarsSchema. Sampled sources expose values at shutter offsets for motion blur.
  • Changes flow as observer notices: PrimsAdded, PrimsRemoved, PrimsDirtied (with data source locators naming what changed) and PrimsRenamed.
  • Prim categories in the render delegate: Rprims (mesh, curves, points, volumes), Sprims (camera, lights, materials, render settings), Bprims (render buffers).
  • Legacy Hydra 1.0 scene delegates still run through an emulation layer, but new work should be scene indices.

Write a filtering scene index

Subclass HdSingleInputFilteringSceneIndexBase, override the queries, forward or edit notices, then wrap it in a scene index plugin.

#include "pxr/imaging/hd/filteringSceneIndex.h"
#include "pxr/imaging/hd/overlayContainerDataSource.h"
#include "pxr/imaging/hd/tokens.h"

PXR_NAMESPACE_OPEN_SCOPE

TF_DECLARE_REF_PTRS(KindTintSceneIndex);

class KindTintSceneIndex : public HdSingleInputFilteringSceneIndexBase
{
public:
    static KindTintSceneIndexRefPtr New(const HdSceneIndexBaseRefPtr &input,
                                        const HdContainerDataSourceHandle &overlay) {
        return TfCreateRefPtr(new KindTintSceneIndex(input, overlay));
    }

    HdSceneIndexPrim GetPrim(const SdfPath &path) const override {
        HdSceneIndexPrim prim = _GetInputSceneIndex()->GetPrim(path);
        if (prim.primType == HdPrimTypeTokens->mesh && prim.dataSource) {
            prim.dataSource = HdOverlayContainerDataSource::New(_overlay, prim.dataSource);
        }
        return prim;
    }

    SdfPathVector GetChildPrimPaths(const SdfPath &path) const override {
        return _GetInputSceneIndex()->GetChildPrimPaths(path);
    }

protected:
    KindTintSceneIndex(const HdSceneIndexBaseRefPtr &input,
                       const HdContainerDataSourceHandle &overlay)
        : HdSingleInputFilteringSceneIndexBase(input), _overlay(overlay) {}

    void _PrimsAdded(const HdSceneIndexBase &,
                     const HdSceneIndexObserver::AddedPrimEntries &e) override { _SendPrimsAdded(e); }
    void _PrimsRemoved(const HdSceneIndexBase &,
                       const HdSceneIndexObserver::RemovedPrimEntries &e) override { _SendPrimsRemoved(e); }
    void _PrimsDirtied(const HdSceneIndexBase &,
                       const HdSceneIndexObserver::DirtiedPrimEntries &e) override { _SendPrimsDirtied(e); }

private:
    HdContainerDataSourceHandle _overlay;   // e.g. a displayColor primvar built with HdPrimvarsSchema
};

PXR_NAMESPACE_CLOSE_SCOPE

Register the plugin for a renderer with HdSceneIndexPluginRegistry::GetInstance().RegisterSceneIndexForRenderer(rendererDisplayName, pluginId, inputArgs, insertionPhase, InsertionOrderAtStart). The insertion phase is an integer: lower runs earlier in the chain. Apps call AppendSceneIndicesForRenderer() to build the chain, and from v26.11 can pass sceneIndexCreateArgs through it to your plugin. v26.11 also adds HdCreateOverlayContainerDataSource as the general way to overlay data sources.

AOVs for synthetic data

Hydra's AOV tokens include color, depth, primId, instanceId, elementId, normal, Neye and Peye. ID buffers map back to prim paths, which gives you segmentation masks without a separate pass. From v26.11 the numeric prim ID is computed by HdsiPrimIdSceneIndex, so read it from the terminal scene index instead of HdRenderIndex::GetRprimPathFromPrimId(). Describe outputs renderer-neutrally with RenderSettings, RenderProduct and RenderVar prims.

Extending USD

Every extension is a plugin found through plugInfo.json on PXR_PLUGINPATH_NAME. Build C++ plugins against the exact OpenUSD build of the host app: Houdini, Unreal, Omniverse and your own build each ship different versions and namespaces.

1. A codeless schema

No compiler: define the schema, generate its definition, point the plugin path at it. Good for studio metadata and API schemas.

Don't duplicate built-ins. Class labels already have a standard home: SemanticsLabelsAPI:<taxonomy> with token[] semantics:labels:<taxonomy>. It has no instance or track ID, so the example below adds only that.
#usda 1.0
(
    subLayers = [@usd/schema.usda@]
)

over "GLOBAL" (
    customData = {
        string libraryName = "studioLabels"
        string libraryPath = "."
        bool skipCodeGeneration = true
    }
)
{
}

class "TrackLabelAPI" (
    inherits = </APISchemaBase>
    customData = {
        token apiSchemaType = "singleApply"
    }
    doc = "Stable track id for synthetic-data ground truth. Pair with SemanticsLabelsAPI for classes."
)
{
    int label:trackId = -1 (doc = "Stable instance id across frames.")
}
usdGenSchema schema.usda ./studioLabels      # writes generatedSchema.usda + plugInfo.json
export PXR_PLUGINPATH_NAME=$PWD/studioLabels:$PXR_PLUGINPATH_NAME
python -c "from pxr import Usd; print(Usd.SchemaRegistry().FindAppliedAPIPrimDefinition('TrackLabelAPI'))"
prim.ApplyAPI("TrackLabelAPI")                     # codeless schemas apply by name
prim.GetAttribute("label:trackId").Set(17)

prim.ApplyAPI("SemanticsLabelsAPI", "class")       # built-in, multiple-apply
prim.GetAttribute("semantics:labels:class").Set(["forklift", "vehicle"])

2. A compiled schema

  • Remove skipCodeGeneration, set libraryPath, and usdGenSchema writes C++ classes, Python wrappers, tokens and plugInfo.json with a LibraryPath.
  • Build with CMake: find_package(pxr CONFIG REQUIRED), link usd, sdf, tf; match the host's compiler, C++ standard and Python ABI.
  • You get typed accessors (TrackLabelAPI::GetLabelClassAttr()) and schema fallbacks inside C++ tools and Hydra plugins.

3. A file format plugin

Make any file readable as a layer. The pattern: parse the file, author specs into an anonymous layer, transfer them in.

TF_DEFINE_PRIVATE_TOKENS(_tokens,
    ((Id, "ply")) ((Version, "1.0")) ((Target, "usd")) ((Ext, "ply")));

class PlyFileFormat : public SdfFileFormat
{
public:
    bool CanRead(const std::string &path) const override { return true; }

    bool Read(SdfLayer *layer, const std::string &resolvedPath,
              bool metadataOnly) const override {
        SdfLayerRefPtr tmp = SdfLayer::CreateAnonymous(".usda");
        // parse resolvedPath; author a ParticleField3DGaussianSplat prim with Sdf API
        layer->TransferContent(tmp);
        return true;
    }

    bool WriteToString(const SdfLayer &layer, std::string *str,
                       const std::string &comment) const override {
        return SdfFileFormat::FindById(UsdUsdaFileFormatTokens->Id)
            ->WriteToString(layer, str, comment);   // show contents as usda
    }

protected:
    SDF_FILE_FORMAT_FACTORY_ACCESS;
    PlyFileFormat()
        : SdfFileFormat(_tokens->Id, _tokens->Version, _tokens->Target, _tokens->Ext) {}
};

stage = Usd.Stage.Open("set.usda")

mesh.GetPointsAttr().Set(Vt.Vec3fArray.FromNumpy(pts))

bb_cache = UsdGeom.BBoxCache(Usd.TimeCode(1), [UsdGeom.Tokens.default_, UsdGeom.Tokens.render])
print(xf_cache.GetLocalToWorldTransform(robot), bb_cache.ComputeWorldBound(robot))

Verify any schema yourself

Docs and release blogs drift from the code. The schema registry is the source of truth: it lists a schema's real usda name, kind, properties, types and fallbacks.

# pip install usd-core   (then: python verify.py BackPlateAPI)
import sys
from pxr import Usd, Tf

reg = Usd.SchemaRegistry()
name = sys.argv[1]
d = reg.FindConcretePrimDefinition(name) or reg.FindAppliedAPIPrimDefinition(name)
if not d:
    hits = [t.typeName for t in Tf.Type.Find(Usd.SchemaBase).GetAllDerivedTypes()
            if name.lower() in t.typeName.lower()]
    sys.exit(f"No schema '{name}'. C++ types that match: {hits}")
print("version:", Usd.GetVersion(), " built-in APIs:", list(d.GetAppliedAPISchemas()))
for p in d.GetPropertyNames():
    spec = d.GetSchemaPropertySpec(p)
    if hasattr(spec, "typeName"):
        print(f"{p}: {spec.typeName}  fallback={d.GetAttributeFallbackValue(p)}")
    else:
        print(f"{p}: rel")

Multiple-apply schemas print their properties with an __INSTANCE_NAME__ placeholder. To prove a snippet is valid, load it: Sdf.Layer.CreateAnonymous(".usda").ImportFromString(text) raises on any syntax error.
